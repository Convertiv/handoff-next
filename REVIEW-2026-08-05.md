**The clean-canvas fix, and why it isn't a deletion.** The old code restored
`localStorage['handoff-playground-components']` on mount, which is why "New" reopened old work. Deleting
the key outright would have thrown away anyone's unsaved canvas on the deploy that shipped it — so it is
now read **into an offer**: a banner saying "You have an unsaved canvas from a previous visit (N blocks)"
with *Restore it* / *Start fresh*. Either choice clears the key, so it appears at most once, and a page
opened by id never shows it (the record is the truth there).

**Autosave scope, deliberately narrow.** It writes `components` + `data` only — never title/description/
group/tags, because those are edited elsewhere and sending empty strings would wipe them. It also refuses
to fire on the first observation after a load, or the load itself would immediately save what it just read.
A failed save shows "Not saved" rather than retrying silently.

### Roadmap E.2 — one save path, and templates as separate objects (BUILT, needs your eyes)

Built to your reframing: **"save this page as a template"** creates a *separate, frozen, team-visible
copy*. Your page carries on as yours. That also fixes something I'd flagged — a frozen template means a
guest submission's diff stays stable instead of shifting under whoever reviews it next.

| File | What |
|---|---|
| `src/app/lib/db/pattern-write.ts` | `savePageAsTemplate` (new record: `source: 'template'`, `visibility: 'team'`, snapshot of blocks + guardrails) and the **freeze guard** in `patchPattern` |
| `src/app/app/actions/patterns.ts` | `savePatternAsTemplate` server action |
| `src/app/components/Playground/PlaygroundContext.tsx` | **save on first block** — creates the record, redirects to `/playground/{id}` |
| `src/app/components/Playground/PlaygroundBuilder.tsx` | save button → **Save as template**; static mode keeps an explicit save; result notice |
| `src/app/app/api/handoff/patterns/[id]/clone/route.ts` | a clone of a template now records `template_id`, so editor pages are diffable like guest ones |
| `src/app/app/library/LibraryClient.tsx` etc. | wording: "New page", "Pages" |

**The freeze is enforced in the write core, not the UI** — because autosave reaches `patchPattern`, so
opening a template and nudging a block would otherwise rewrite the team's standard silently. Verified
against the DB, eight behaviours:

1. template created with `source: template`, `visibility: team`, blocks **and guardrails** copied
2. source page untouched (still `playground`, still `private`, same title)
3. editing the page still works
4. editing template **content** → refused
5. an autosave-shaped write (`data` only) to a template → refused
6. an administrative meta change (archive) → still allowed, correctly
7. templating a template → refused with a useful message
8. provenance recorded: `{action: 'save-as-template', fromPageId}` — *not* in `template_id`, which means
   "built from" and would have inverted every diff that reads it

Decisions I made rather than asking, flag if you disagree: a template is created `status: 'draft'` (setting
`approved` here would route around the maintainer-gated approve path); anyone who can edit a page can
template it (the dangerous act — sending a link outside the team — is separately gated); and the
browser-local template *creation* path is gone while existing local templates stay loadable, so they can be
converted rather than lost. **Full removal of that code path is the one piece of E.2 still outstanding.**
