**The clean-canvas fix, and why it isn't a deletion.** The old code restored
`localStorage['handoff-playground-components']` on mount, which is why "New" reopened old work. Deleting
the key outright would have thrown away anyone's unsaved canvas on the deploy that shipped it — so it is
now read **into an offer**: a banner saying "You have an unsaved canvas from a previous visit (N blocks)"
with *Restore it* / *Start fresh*. Either choice clears the key, so it appears at most once, and a page
opened by id never shows it (the record is the truth there).

**Autosave scope, deliberately narrow.** It writes `components` + `data` only — never title/description/
group/tags, because those are edited elsewhere and sending empty strings would wipe them. It also refuses
to fire on the first observation after a load, or the load itself would immediately save what it just read.
A failed save shows "Not saved" rather than retrying silently.
